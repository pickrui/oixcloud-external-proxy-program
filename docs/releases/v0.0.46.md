本次为 v0.0.46 同版本修订，修复更新并重启后菜单栏只剩空白占位、图标消失且无法打开菜单的问题

- 更新后启动全新的菜单栏进程，避免沿用旧 PID 导致 macOS 菜单栏场景连接失效
- 按当前进程识别实际 launchd 启动项，兼容安装脚本与 Homebrew；手动启动时保留端口和配置路径，启动失败时保留旧进程
- Homebrew Formula 增加 revision，已有 v0.0.46 安装也可获取本次修订

首次从旧构建更新时，仍会执行旧进程中的重启逻辑；若图标再次空白，完整退出并重新启动一次即可，本次修订运行后将使用新的重启流程

保留 main 和 Legacy 的网络诊断日志，用于定位 #37 中的 DNS 连接失败；尚未确认修复受影响设备上的原问题

- 区分出口选择（`stage=select`）、网卡绑定（`stage=bind`）和 DNS 查询（`stage=query`）失败，记录系统错误码、路由状态和耗时
- 覆盖认证 DNS 的 UDP / TCP 回退、系统 DNS 与 ECH 查询，通过查询标识关联同一次认证 DNS 请求的失败过程
- 诊断同时写入标准错误输出和系统日志，便于从现有菜单栏、Homebrew、Surge 或 Docker 日志收集；新增诊断不输出签名查询名、凭据和实际节点地址

macOS 12 / 13 用户请升级 Legacy 通用版，在原有 Surge 设置下复现后，提供失败时间附近的 `[Network]` 日志与系统、Surge 版本，反馈至 [issue #37](https://github.com/pickrui/oixcloud-external-proxy-program/issues/37)

macOS 提供 Apple Silicon、Intel（macOS 14+）及 Legacy 通用版（macOS 12+），均使用 Developer ID 签名，并附 SHA256SUMS

Docker：`ghcr.io/pickrui/oixcloud-external-proxy-program:v0.0.46` 和 `latest`，支持 `linux/amd64`、`linux/arm64`
