# v0.0.59

## 中文

- 整理 macOS 菜单栏，将刷新、筛选和单端口测速集中到「节点」，将 Surge、OpenSurge 和节点列表集中到「客户端接入」，将端口、局域网、开机启动和语言集中到「设置」，未登录时可从菜单首页直接登录
- Helper 后台和新导出的 OpenSurge 节点 Provider 默认每 24 小时更新，使用缓存节点的单端口进程和使用固定映射端口的服务会在启动时立即拉取节点
- 修复唤醒或网络切换时，手动刷新节点的结果可能丢失、菜单一直显示「正在更新」的问题
- 修复绑定特定局域网地址时，终端状态检查或 Surge 接入仍使用回环地址的问题
- 写入配置失败时恢复原有钥匙串令牌，避免失败的账号切换覆盖已保存的登录

### 升级

- 启动器或手动安装可用「工具 › 检查更新」
- Homebrew 可执行 `brew update`、`brew upgrade oixcloud-external-proxy-program`，然后重启服务
- Docker 可执行 `docker compose pull` 和 `docker compose up -d`

OpenSurge 已导入的配置需通过「客户端接入 › 导出 OpenSurge 配置」重新导出并导入，或将 Provider 的 `interval` 改为 `86400`

## English

- Reorganize the macOS menu bar. Nodes groups refresh, filtering, and single-port latency tests. Client Setup groups Surge, OpenSurge, and the node list. Settings covers ports, LAN access, startup at login, and language. Sign-in is available directly from the main menu
- Refresh nodes every 24 hours by default in the helper and newly exported OpenSurge providers. Single-port processes using a cached node and services using fixed mapped ports now fetch nodes on startup
- Fix manual refresh results being dropped when the Mac wakes or switches networks, which could leave the menu stuck on “Refreshing nodes…”
- Use the configured LAN address for terminal readiness checks and Surge setup when the listener is bound to a specific address
- Restore the previous Keychain token if saving the configuration fails during an account change

### Upgrade

Launcher and manual installations can use Tools > Check for updates. For Homebrew, run `brew update`, `brew upgrade oixcloud-external-proxy-program`, and restart the service. For Docker, run `docker compose pull` and `docker compose up -d`

For an existing OpenSurge profile, export a fresh copy from Client Setup > Export OpenSurge config and import it, or set the provider’s `interval` to `86400`
